04

Kesinlikle Yapılması Gerekenler

1. Her işi küçük parçalara böl

AI'a "bu modülü komple yeniden yaz" demek yerine "şu acceptance criteria'ya sahip küçük vertical slice'ı tamamla" demek gerekir.

2. Token ve context kullanımını gözlemle

Uzun session'larda modelin performansı düşer. Kalite düşüşü belirtileri: tekrarlayan hatalar, daha önce verdiği kararları unutması, alakasız kod üretmesi. Bu belirtiler görüldüğünde session'ı temizleyip yeni context ile devam et. Araç destekliyorsa token kullanımını görünür kıl.

3. Kod tabanını AI için okunabilir hâle getir

İyi isimlendirilmiş modüller, sade interface'ler, net test sınırları, güncel README ve local development komutları agent başarısını doğrudan artırır.

4. PRD ve issue artefact'larını dosya olarak tut

AI ile konuşmada kalmış kararlar kaybolur. Kararlar Markdown issue, PRD, ADR veya test planı olarak repository içinde kalıcılaşmalıdır.

5. AI'a test komutlarını açıkça ver

text — TypeScript/JS
After implementation, run:
- npm test
- npm run typecheck
- npm run lint
- npm run build
text — Python
After implementation, run:
- pytest
- ruff check .
- mypy .

6. Review'u asla atlama

AI daha çok kod ürettikçe review yükü artar. İnsan review ve QA, kaliteyi ve "taste" dediğimiz mühendislik sezgisini korur — kodun sadece çalışıp çalışmadığını değil, doğru tasarlanıp tasarlanmadığını, sürdürülebilir olup olmadığını ve ekip standartlarına uyup uymadığını değerlendirir.

05

Kesinlikle Yapılmaması Gerekenler

1. "Tek prompt ile komple feature" yaptırma

Context'i şişirir, scope'u büyütür ve modelin kontrolünü zorlaştırır.

2. Sadece spec'i düzeltip kodu okumadan ilerleme

Bu yaklaşım developer'ı koddan koparır. Kod hâlâ ana gerçekliktir. Spec-first, API contract ve migration planı gibi alanlarda doğrudur; ama spec yazdıktan sonra üretilen kodu da okumak ve anlamak gerekir.

3. Testsiz AI kodunu merge etme

AI'ın ürettiği kod derleniyor olabilir ama doğru davranıyor olmayabilir. Test, typecheck ve build olmadan güvenilmez.

4. Horizontal phase plan'a körü körüne uyma

Sadece database → sonra API → sonra frontend giden plan feedback'i geciktirir. Vertical slice tercih edilmelidir.

5. Büyük CLAUDE.md / system prompt dosyaları oluşturma

CLAUDE.md, .cursorrules gibi dosyalar küçük tutulmalıdır. Başlangıç context'i çok büyükse model daha işe başlamadan effective attention kapasitesini tüketmeye başlar.

6. Stale dokümanları repo'da başıboş bırakma

Eski PRD'ler veya kapanmış karar dokümanları AI'ı yanıltabilir. PRD'ler implementation sonrası kapatılıp arşivlenmelidir.

06

Önerilen AI Coding Playbook

Basit feature için
  • 1Brief'i oku.
  • 2Beni sorgula, eksik kararları çıkar.
  • 3PRD üret.
  • 4PRD'yi vertical slice issue'larına böl.
  • 5İlk issue'yu TDD ile uygula.
  • 6Test / typecheck / build çalıştır.
  • 7Summary yaz.
  • 8Ben review edeceğim.
Daha büyük feature için
  • 1Domain expert + developer + AI ile grilling session.
  • 2PRD oluştur.
  • 3Teknik spike gerekiyorsa prototype yap.
  • 4PRD'yi Kanban issue'larına böl.
  • 5Issue'ları dependency graph olarak sırala.
  • 6Bağımsız issue'ları paralel agent'lara ver.
  • 7Her agent kendi branch / worktree / sandbox içinde çalışsın.
  • 8Test ve build sinyalleri zorunlu olsun.
  • 9Merge öncesi human review.
  • 10PRD / issue kapat, dokümanı arşivle.
07

AI Coding Beceri Haritası

Aşağıdaki beceri alanları lineer bir sıralama değil, bağımsız geliştirilebilecek boyutlardır. Bir senior developer doğrudan D veya E boyutundan başlayabilir. Kendi deneyim ve ihtiyacına göre öncelik belirlemelisin.

A
AI ile Pair Programming
AI'ı autocomplete değil, düşünce partneri olarak kullanmak
Temel programlama

Çalışılacak konular

  • Prompt yazma
  • Küçük refactor yaptırma
  • Unit test yazdırma
  • Hata mesajı analiz ettirme
  • Kod açıklatma
  • Alternatif çözüm karşılaştırma

Pratik görev

görev

AI'dan önce test yazmasını iste.
Sonra fonksiyonu refactor ettir.
Sonra edge case testleri eklet.

B
Structured Prompting
AI'a serbest kod yazdırmak yerine formatlı görev vermek
Temel AI deneyimi

Öğrenilecek kalıplar

  • Role
  • Context
  • Goal
  • Constraints
  • Acceptance Criteria
  • Test Plan
  • Output Format

Örnek yapı

örnek
Role: Senior backend developer
Context: FastAPI + PostgreSQL project
Goal: Add user activity logging
Constraints:
- Do not change public API
- Keep changes minimal
- Add tests
Acceptance Criteria:
- Login event is logged
- Failed login is logged
- Tests pass
Output:
- Changed files
- Test results
- Summary
Kimler için Herkes; özellikle prompt kalitesini artırmak isteyenler.

Solo developer

Tüm alanlar tek kişide toplanır. Bu durumda AI agent'ı "ikinci göz" olarak kullanmak faydalıdır: agent'a kendi kodunu farklı bir session'da review ettirmek, eksik test önerisi istemek gibi.

Örnek AI Coding Session Akışı

Tüm aşamaların pratikte nasıl bir konuşma akışına dönüştüğünü gösteren bir örnek. Senaryo: bir eğitim platformuna basit bir puan sistemi eklenmesi.

Developer

Bu feature brief'ini oku. Kod yazma. Önce beni sorgula.

AI
  • Bu feature hangi kullanıcı segmenti için?
  • Başarı metriği nedir?
  • Existing data geriye dönük işlenecek mi?
  • UI nerede görünecek?
  • Edge case'ler neler?
Developer

Cevapları verir.

AI

PRD üretir → docs/prd/gamification-points.md

Developer

PRD'yi vertical slice issue'larına böl.

AI
  • Issue 01: Minimal end-to-end flow
  • Issue 02: Edge case handling
  • Issue 03: Admin visibility
  • Issue 04: Migration / backfill
  • Issue 05: Tests and cleanup
Developer

Issue 01'i TDD ile uygula. Scope dışına çıkma.

AI

Test yazar → implementation yapar → testleri çalıştırır → summary verir.

Developer

Review eder, düzeltme ister veya merge eder.

10

En Önemli Best Practice'ler

1AI'a doğrudan kod yazdırma; önce seni sorgulamasını iste.
2Plan değil, shared understanding hedefle.
3PRD üret ama PRD'yi yaşayan gerçeklik sanma; gerçeklik koddur.
4Issue'ları vertical slice olarak böl.
5Agent'a küçük, bağımsız, test edilebilir işler ver.
6TDD kullan; AI'a önce test yazdır.
7Context'i küçük tut; uzun session'lara güvenme.
8Sub-agent kullanırken parent context'i temiz tut.
9Deep module mimarisi kur; shallow dependency çorbasından kaçın.
10Human review ve QA'yı sürecin zorunlu parçası yap.
11AFK coding koşulsuz güvenli değildir; branch izolasyonu, iteration limiti ve diff review zorunludur.
11

Kısa Özet

AI coding'in özü "prompt yazmayı bilmek" değildir. Asıl mesele şudur:

AI'a doğru işi, doğru boyutta, doğru bağlamla, doğru feedback loop içinde yaptırmak.

Bu yüzden başarılı AI coding süreci şu formüle indirgenebilir:

Align­ment
→
PRD
→
Vertical Slice Issues
→
TDD Impl.
→
Auto Checks
→
Human Review
→
Merge

AI coding, disiplinsiz geliştiriciyi otomatik olarak iyi geliştirici yapmaz. Tam tersine, disiplinsizliği büyütür. Ama iyi yazılım mühendisliği pratikleriyle birleştiğinde; doğru planlanmış, test edilebilir, küçük ve bağımsız iş parçalarını çok hızlı hayata geçiren güçlü bir üretim modeline dönüşür.

Bölüm 1 ile birlikte değerlendirildiğinde bu çerçeve, herhangi bir dil veya araç seçimine bağlı kalmaksızın agentic software delivery workflow'u kurmanın temelini oluşturur.
