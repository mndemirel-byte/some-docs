02

Klasörlerin Sorumlulukları

CLAUDE.md
Ana agent manifest. Proje amacı, mimari kurallar, test komutları, skill ve agent workflow'u, agent sınırları. Uzun prosedürler skills/*/SKILL.md'ye gider.
.claude/skills/
Tekrar kullanılabilir çalışma disiplinleri. Skill bir "rol" değil, agent'ın uygulayacağı prosedürdür.
.claude/agents/
Uzman agent rolleri. Her agent belirli bir işi üstlenir ve birden fazla skill kullanabilir.
docs/CONTEXT.md
Yaşayan bağlam dosyası. Domain dili, önemli kavramlar, sistem sınırları, modül sorumlulukları ve mimari kabuller.
docs/prd/
Ürün gereksinim dokümanları. Ör: 001-initial-product-requirements.md
docs/issues/
Agent'lara verilecek iş parçaları. Her issue vertical slice olmalı — yatay katman görevi olmamalı.
docs/adr/
Architecture Decision Records. Ör: 0001-use-config-file-for-pricing.md
docs/architecture/
Sistem mimarisi, modül haritası, veri akışı, sequence diagram ve high-level design dokümanları.
docs/decisions/
ADR seviyesinde olmayan ama takip edilmesi gereken küçük ürün, teknik veya süreç kararları.

04

CLAUDE.md Şablonu

Aşağıdaki içeriği proje kökündeki CLAUDE.md dosyasına koy.

CLAUDE.md
Project Instructions for Claude Code
Tam şablonu görmek için genişlet
markdown 
# Project Instructions for Claude Code

## Project Goal
This repository uses an agentic development workflow.
Claude should not work as a single monolithic coding assistant. Instead, Claude should:
1. Understand the project context.
2. Clarify requirements.
3. Produce PRDs when needed.
4. Break work into vertical slice issues.
5. Implement one issue at a time.
6. Use TDD for deterministic behavior.
7. Keep architecture decisions documented.
8. Review architecture before finalizing milestones.

## Repository Structure
Important folders:
- `docs/CONTEXT.md`: living project context and domain language
- `docs/prd/`: product requirements documents
- `docs/issues/`: agent-ready vertical slice implementation issues
- `docs/adr/`: architecture decision records
- `docs/architecture/`: high-level design and architecture notes
- `docs/decisions/`: smaller non-ADR decisions
- `.claude/skills/`: reusable workflows and engineering disciplines
- `.claude/agents/`: specialized project agents

## Default Workflow
For new features:
1. Use `/grill-with-docs` if the requirement is unclear.
2. Use `/to-prd` for medium or large features.
3. Use `/to-issues` to split PRD into vertical slice issues.
4. Use `implementation-agent` for implementation.
5. Implementation must follow `/tdd`.
6. Use `/codebase-design` when changing module boundaries.
7. Use `debugging-agent` with `/diagnosing-bugs` when tests fail unexpectedly.
8. Use `/improve-codebase-architecture` before milestone completion.

## Architecture Rules
- Prefer vertical slices over horizontal layer work.
- Keep business logic separate from presentation layers.
- Keep public interfaces small.
- Prefer deep modules over shallow modules.
- Avoid unnecessary abstraction.
- Avoid large rewrites unless explicitly requested.
- Do not duplicate business logic across UI, API, CLI, or worker layers.
- Document meaningful architecture decisions in `docs/adr/`.

## Testing Rules
- Use TDD for deterministic business logic.
- Write one failing test before implementation.
- Prefer behavior-focused tests.
- Do not couple tests to private implementation details unless necessary.
- Run relevant tests after each change.
- Run the full test suite before marking an issue complete.

## Documentation Rules
- Keep `docs/CONTEXT.md` updated when domain language or module boundaries change.
- Write PRDs under `docs/prd/`.
- Write implementation issues under `docs/issues/`.
- Write ADRs under `docs/adr/`.
- Keep README accurate for setup and usage.

## Issue Rules
Issues under `docs/issues/` must include:
- Title, User story, Acceptance criteria, Test expectations,
  Dependencies, Suggested agent, Required skills, Out of scope

Issues should be vertical slices. Avoid: "Create database layer", "Write pricing.py".
Prefer: "User can run the first CLI tracer bullet and see a cost estimate".

## Commands
```bash
# Run tests
pytest

# Run app
# TODO: add project-specific run command
```

## Safety and Scope
- Do not delete files without explicit instruction.
- Do not introduce new dependencies without explaining why.
- Do not change public behavior outside the active issue.
- Do not perform unrelated refactors.
- If a task is too broad, create or update an issue instead of coding immediately.

06

Skill Dosyaları

Aşağıdaki dosyalar .claude/skills/<skill-name>/SKILL.md altında tutulur. Detaylar için genişlet.

skill
grill-with-docs
Belirsiz gereksinimi netleştir, domain dili oluştur

Amaç: PRD oluşturmadan önce proje niyetini netleştirmek.

Ne zaman kullanılır:

  • Gereksinim geniş veya belirsizse
  • Proje sınırları net değilse
  • Agent varsayım yapmak üzereyse
  • Paylaşılan domain dili eksikse
  • Kullanıcı plan istedi ama önemli detaylar eksik

Çıktılar: docs/CONTEXT.md, docs/decisions/, opsiyonel docs/adr/ taslakları

Talimatlar:

  1. Varsa mevcut dokümanları oku: docs/CONTEXT.md, docs/prd/, docs/adr/, README.md
  2. Belirle: proje hedefi, hedef kullanıcılar, core workflow'lar, domain vocabulary, kısıtlamalar, varsayımlar, açık sorular
  3. Yalnızca en önemli netleştirici soruları sor
  4. Yeterli bağlam varsa docs/CONTEXT.md'yi güncelle

Kurallar: Kod implemente etme. Issue oluşturma (talep edilmediğinde). Uzun yazılar yerine özlü bağlam tercih et. Gerçekleri, varsayımları ve açık soruları birbirinden ayır.

skill
to-prd
Feature fikrini PRD'ye çevir

Amaç: Mevcut proje bağlamından PRD oluşturmak.

Girdiler: docs/CONTEXT.md, docs/decisions/, docs/adr/, README.md, mevcut konuşmadaki kullanıcı isteği

Output konum: docs/prd/NNN-feature-name.md

PRD yapısı (zorunlu alanlar):

  • Title, Problem statement, Goals, Non-goals
  • Target users, User stories
  • Functional requirements, Non-functional requirements
  • UX/interface expectations, Data/config requirements
  • Acceptance criteria, Out of scope, Open questions

Kurallar: Kod implemente etme. Dosya bazlı implementation planı yapma. Teknik detayı modül sınırı seviyesinde tut. Bağlam yetersizse grill-with-docs çalıştır.

skill
to-issues
PRD'yi vertical slice issue'lara böl

Girdiler: docs/prd/, docs/CONTEXT.md, ilgili ADR'lar

Output: docs/issues/NNN-short-title.md

Issue yapısı: Title, User story, Background, Acceptance criteria, Test expectations, Dependencies, Suggested agent, Required skills, Out of scope, Done checklist

Issue'lar vertical slice olmalıdır. "Create database layer" veya "Write pricing.py" DEĞIL; "User can load model pricing from config and get a cost estimate" gibi davranış odaklı issue'lar tercih edilir.
skill
tdd
Red-green-refactor döngüsü ile implementation

Amaç: Implementation'ı red-green-refactor döngüsü ile yönlendirmek.

Adımlar:

  1. Issue acceptance criteria'yı oku
  2. Bir davranış seç
  3. Bir failing test yaz
  4. İlgili test komutunu çalıştır
  5. Testin beklenen nedenle başarısız olduğunu doğrula
  6. Testi geçirmek için en küçük değişikliği implement et
  7. Testi tekrar çalıştır
  8. Test geçtikten sonra refactor yap
  9. Acceptance criteria tümüyle kapsanana kadar tekrarla
  10. Bitirmeden önce tam test suite'ini çalıştır

Test kuralları: Davranış testleri tercih et. Private implementation detaylarını test etme. Brittle test yazma. Değişken değerlere assert etme. Fixture kullan. Testleri okunabilir tut.

Implementation kuralları: Testlerden önce büyük üretim kodu yazma. İlgisiz feature ekleme. İlgisiz refactor yapma. Aktif issue'ya odaklı kal.

skill
codebase-design
Modül sınırlarını ve temiz tasarımı koru

Tasarım prensipleri:

  • Küçük public interface'li derin modülleri tercih et
  • Business logic'i delivery mechanism'lardan (UI, CLI, API, DB) ayır
  • Adapter'ları ince tut
  • Business logic'i tekrar etme
  • Gereksiz soyutlamadan kaçın
  • Domain dilinden açık isimler kullan
  • Hem insanların hem agent'ların kolayca navigate edebildiği kod yaz

ADR tetikleyicileri: Framework seçimi, persistence stratejisi, modül sınırı tanımı/değişimi, public interface stabilizasyonu, gelecek agent'ların anlaması gereken tradeoff.

skill
diagnosing-bugs
Hataları sistematik olarak teşhis et

Bug teşhis adımları:

  1. Hatayı yeniden oluştur
  2. Tam hata mesajını yakala
  3. En küçük başarısız komut veya testi belirle
  4. Son değişiklikleri incele
  5. Hipotez oluştur
  6. Hipotezi doğrulayan / çürüten en küçük değişikliği yap
  7. Başarısız testi tekrar çalıştır
  8. Ancak sonra fix uygula
  9. Yakın testleri çalıştır, tam suite ile bitir

Kurallar: Büyük bölümleri tahmin edip yeniden yazma. Birden fazla ilgisiz bug'ı aynı anda düzeltme. Hatayı anlamadan bastırma. Fix'ten önce regression test eklemeyi tercih et. Şaşırtıcı root cause'ları docs/decisions/'a kaydet.

skill
improve-codebase-architecture
Milestone öncesi mimari gözden geçirme

Review alanları: Modül sınırları, duplicate business logic, shallow modules, framework leakage into core logic, missing tests, confusing names, missing ADRs, inaccurate README, overengineering, under-documented decisions.

Çıktı formatı:

  1. Bulgular — severity bazlı: critical / important / minor
  2. Önerilen düzeltmeler
  3. Kullanıcı onaylamadan yalnızca low-risk fix'leri uygula
  4. Mimari değiştiyse doc'ları güncelle
  5. Değişiklikler sonrası testleri çalıştır

Kurallar: Açık onay olmadan büyük yeniden yazma yapma. Bug düzeltmesi dışında public davranışı değiştirme. Küçük, geri alınabilir refactor'ları tercih et. Mevcut testleri koru.

Agent Tanımları

Aşağıdaki dosyalar .claude/agents/*.md altında tutulur. Agent = rol / uzman worker.

agent
planner-agent
Gereksinim netleştirme, PRD ve issue — kod yazmaz

Model: sonnet  ·  Effort: high  ·  Tools: Read, Write, Edit, Glob, Grep

Skills: grill-with-docs, to-prd, to-issues, codebase-design

Sorumluluklar:

  • Belirsiz gereksinimleri netleştir
  • docs/CONTEXT.md'yi güncelle
  • docs/prd/ altına PRD yaz
  • PRD'yi vertical slice issue'lara böl → docs/issues/
  • Mimari kararlar için docs/adr/ altında ADR taslağı oluştur

Kurallar: Talep edilmediğinde production kodu yazma. Yatay katman issue'ları oluşturma. Tracer bullet issue'ları tercih et. Her issue acceptance criteria ve test expectations içermeli.

agent
implementation-agent
TDD ile tek scoped issue implement eder

Model: sonnet  ·  Effort: high  ·  Tools: Read, Write, Edit, Bash, Glob, Grep

Skills: tdd, codebase-design

Sorumluluklar:

  • Bir seferde tek issue implement et
  • Kodlamadan önce issue dosyasını oku
  • Acceptance criteria'yı tam olarak uygula
  • TDD kullan, her değişiklik sonrası ilgili testleri çalıştır
  • Davranış, komutlar veya mimari değiştiğinde doc'ları güncelle

Kurallar: İlgisiz refactor başlatma. Business logic'i tekrar etme. İlgisiz issue'ları karıştırma. Neden açıklamadan dependency ekleme. Bitirmeden önce tam test suite'ini çalıştır.

agent
debugging-agent
Test hataları ve beklenmedik davranışları teşhis eder

Model: sonnet  ·  Effort: high  ·  Tools: Read, Write, Edit, Bash, Glob, Grep

Skills: diagnosing-bugs, tdd, codebase-design

Sorumluluklar: Bug'ı yeniden oluştur → En küçük failing test'i bul → Kod değiştirmeden önce teşhis et → Uygunsa regression test ekle → En küçük güvenli fix'i uygula → Yakın + tam testleri çalıştır

Kurallar: Büyük bölümleri yeniden yazma. Kodu anlamadan hataları bastırma. İlgisiz sorunları düzeltme. Şaşırtıcı bulguları issue notlarına veya docs/decisions/'a kaydet.

agent
architecture-review-agent
Milestone öncesi final mimari gözden geçirme

Model: sonnet  ·  Effort: high  ·  Tools: Read, Write, Edit, Bash, Glob, Grep

Skills: improve-codebase-architecture, codebase-design

Sorumluluklar:

  • Mimariyi, modül sınırlarını, testleri, doc'ları ve ADR'ları gözden geçir
  • Duplication, coupling ve overengineering'i tespit et
  • Sadece low-risk fix'leri uygula

Kurallar: Onaysız büyük yeniden yazma yapma. Bug düzeltmesi dışında public davranışı değiştirme. Bulguları severity bazlı grupla. Değişikliklerden sonra testleri çalıştır.

agent
documentation-agent
README, ADR ve proje dokümantasyonunu günceller

Model: sonnet  ·  Effort: medium  ·  Tools: Read, Write, Edit, Glob, Grep

Skills: codebase-design

Sorumluluklar:

  • README'yi güncel tut, kullanım komutlarını güncelle
  • docs/CONTEXT.md'yi güncelle
  • ADR'ları oluştur veya cilala
  • Doc'ları gelecek agent'lar için özlü ve yararlı tut
  • İlgili PRD, ADR ve issue'ları birbirine bağla

Kurallar: Var olmayan davranışı icat etme. Mümkünse komutları codebase'e karşı doğrula. Özlü dokümantasyonu tercih et. İlgili PRD, ADR ve issue'ları linkle.

Kullanım Prensipleri

Skill nedir?

Çalışma disiplini veya prosedürdür. tdd bir skill'dir. codebase-design bir skill'dir.

Agent nedir?

Rol veya uzman worker'dır. implementation-agent bir agent'tır. tdd ve codebase-design skill'lerini kullanır.

Project-level setup

Her repo içinde .claude/skills/, .claude/agents/, CLAUDE.md ve docs/ tutulur. Proje kendi agentic workflow'unu taşır.

Personal-level setup

Aynı tanımları tüm projelerde global kullanmak için ~/.claude/skills/ ve ~/.claude/agents/. Ancak ekip projelerinde project-level daha güvenlidir.

Anti-pattern'ler

Kaçın
Bana tüm uygulamayı yap.
Tercih et
Use planner-agent to create vertical slice issues from the PRD.
Kaçın
pricing.py yaz.
Tercih et
Implement the issue: user can load model pricing from config and get a cost estimate.
Kaçın
Testler kırıldı, düzelt.
Tercih et
Use debugging-agent and diagnosing-bugs. Reproduce the failure, identify the root cause, add a regression test if needed, then fix.
12

Özet

Bu setup'ın hedefi — her adım bir sonrakini besleyen bir agentic delivery pipeline:

Intent
→
Context
→
PRD
→
Issues
→
Agents
→
TDD
→
Review
→
Docs

Bu yapı sayesinde Claude Code:

  • Neyi nereye yazacağını bilir
  • PRD ve issue üretirken standart klasörleri kullanır
  • ADR kararlarını doğru yerde tutar
  • Implementation sırasında TDD uygular
  • Modül sınırlarını korur
  • Milestone sonunda mimari review yapar
Bu, "tek agent'a büyük prompt verme" yaklaşımından çıkıp gerçek bir agentic software delivery workflow kurmanın temelidir.
