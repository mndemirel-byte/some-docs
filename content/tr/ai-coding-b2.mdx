<Section id="s4" num="04" title="Kesinlikle Yapılması Gerekenler">

<DoDontList>
  <DoItem title="1. Her işi küçük parçalara böl">
    <p>AI&apos;a "bu modülü komple yeniden yaz" demek yerine "şu acceptance criteria&apos;ya sahip küçük vertical slice&apos;ı tamamla" demek gerekir.</p>
  </DoItem>
  <DoItem title="2. Token ve context kullanımını gözlemle">
    <p>Uzun session'larda modelin performansı düşer. Kalite düşüşü belirtileri: tekrarlayan hatalar, daha önce verdiği kararları unutması, alakasız kod üretmesi. Bu belirtiler görüldüğünde session'ı temizleyip yeni context ile devam et. Araç destekliyorsa token kullanımını görünür kıl.</p>
  </DoItem>
  <DoItem title="3. Kod tabanını AI için okunabilir hâle getir">
    <p>İyi isimlendirilmiş modüller, sade interface'ler, net test sınırları, güncel README ve local development komutları agent başarısını doğrudan artırır.</p>
  </DoItem>
  <DoItem title="4. PRD ve issue artefact'larını dosya olarak tut">
    <p>AI ile konuşmada kalmış kararlar kaybolur. Kararlar Markdown issue, PRD, ADR veya test planı olarak repository içinde kalıcılaşmalıdır.</p>
  </DoItem>
  <DoItem title="5. AI'a test komutlarını açıkça ver">
    <CodeBlock lang="text — TypeScript/JS" copyLabel="Kopyala" copiedLabel="Kopyalandı">
{`After implementation, run:
- npm test
- npm run typecheck
- npm run lint
- npm run build`}
    </CodeBlock>
    <CodeBlock lang="text — Python" copyLabel="Kopyala" copiedLabel="Kopyalandı">
{`After implementation, run:
- pytest
- ruff check .
- mypy .`}
    </CodeBlock>
  </DoItem>
  <DoItem title="6. Review'u asla atlama">
    <p>AI daha çok kod ürettikçe review yükü artar. İnsan review ve QA, kaliteyi ve "taste" dediğimiz mühendislik sezgisini korur — kodun sadece çalışıp çalışmadığını değil, doğru tasarlanıp tasarlanmadığını, sürdürülebilir olup olmadığını ve ekip standartlarına uyup uymadığını değerlendirir.</p>
  </DoItem>
</DoDontList>

</Section>

<Section id="s5" num="05" title="Kesinlikle Yapılmaması Gerekenler">

<DoDontList>
  <DontItem title='1. "Tek prompt ile komple feature" yaptırma'>
    <p>Context'i şişirir, scope'u büyütür ve modelin kontrolünü zorlaştırır.</p>
  </DontItem>
  <DontItem title="2. Sadece spec'i düzeltip kodu okumadan ilerleme">
    <p>Bu yaklaşım developer'ı koddan koparır. <strong>Kod hâlâ ana gerçekliktir.</strong> Spec-first, API contract ve migration planı gibi alanlarda doğrudur; ama spec yazdıktan sonra üretilen kodu da okumak ve anlamak gerekir.</p>
  </DontItem>
  <DontItem title="3. Testsiz AI kodunu merge etme">
    <p>AI'ın ürettiği kod derleniyor olabilir ama doğru davranıyor olmayabilir. Test, typecheck ve build olmadan güvenilmez.</p>
  </DontItem>
  <DontItem title="4. Horizontal phase plan'a körü körüne uyma">
    <p>Sadece database → sonra API → sonra frontend giden plan feedback'i geciktirir. Vertical slice tercih edilmelidir.</p>
  </DontItem>
  <DontItem title="5. Büyük CLAUDE.md / system prompt dosyaları oluşturma">
    <p><code>CLAUDE.md</code>, <code>.cursorrules</code> gibi dosyalar küçük tutulmalıdır. Başlangıç context'i çok büyükse model daha işe başlamadan effective attention kapasitesini tüketmeye başlar.</p>
  </DontItem>
  <DontItem title="6. Stale dokümanları repo'da başıboş bırakma">
    <p>Eski PRD'ler veya kapanmış karar dokümanları AI'ı yanıltabilir. PRD'ler implementation sonrası kapatılıp arşivlenmelidir.</p>
  </DontItem>
</DoDontList>

</Section>

<Section id="s11" num="11" title="Kısa Özet">

AI coding'in özü "prompt yazmayı bilmek" değildir. Asıl mesele şudur:

<KeyQuote>
  AI'a doğru işi, doğru boyutta, doğru bağlamla, doğru feedback loop içinde yaptırmak.
</KeyQuote>

Bu yüzden başarılı AI coding süreci şu formüle indirgenebilir:

<Formula
  nodes={["Alignment", "PRD", "Vertical Slice Issues", "TDD Impl.", "Auto Checks", "Human Review", "Merge"]}
/>

AI coding, disiplinsiz geliştiriciyi otomatik olarak iyi geliştirici yapmaz. Tam tersine, **disiplinsizliği büyütür.** Ama iyi yazılım mühendisliği pratikleriyle birleştiğinde; doğru planlanmış, test edilebilir, küçük ve bağımsız iş parçalarını çok hızlı hayata geçiren güçlü bir üretim modeline dönüşür.

<Callout icon={IconSparkles} kind="tip">
  Bölüm 1 ile birlikte değerlendirildiğinde bu çerçeve, herhangi bir dil veya araç seçimine bağlı kalmaksızın agentic software delivery workflow'u kurmanın temelini oluşturur.
</Callout>
