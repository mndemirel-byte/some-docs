<Section id="rules" num="05" title="rules">

<code>.claude/rules/</code>, <code>CLAUDE.md</code>'yi şişirmeden kalıcı talimatları modüler dosyalara bölmek için kullanılır. Rules, Claude'un bilmesi gereken davranış/proje kurallarıdır. Ama önemli nüans şu: <strong>path verilmemiş rule dosyaları session başında context'e girer</strong>; <code>paths</code> frontmatter kullanılan rule dosyaları ise Claude ilgili dosyalarla çalışırken yüklenir. Bu yüzden rules klasörü iyi bölünmezse session/context şişirebilir.

<CodeBlock lang="text" kind="file">
{`.claude/
└─ rules/
   ├─ always.md              # tiny global rules; loads every session
   ├─ testing.md             # general test rules; loads every session if no paths
   ├─ frontend/
   │  └─ react.md            # path-scoped to React/TSX files
   └─ backend/
      └─ api.md              # path-scoped to API files`}
</CodeBlock>

<Callout kind="info">
  <strong>Frontmatter neden önemli?</strong> Rule dosyası markdown'dır; başına YAML frontmatter koyabilirsin. En pratik alan <code>paths</code>. <code>paths</code> yoksa rule genel kabul edilir ve session başında yüklenebilir. <code>paths</code> varsa Claude bu rule'u sadece eşleşen dosyalarla çalışırken context'e alır. Amaç: her şeyi baştan okutmak yerine Claude'un o an ihtiyaç duyduğu kuralı okutmak.
</Callout>

<CodeBlock lang="markdown" kind="file">
{`---
paths:
  - "src/api/**/*.ts"
  - "app/api/**/*.ts"
  - "server/**/*.ts"
---

# API Rules

- Validate request input at the boundary.
- Return the shared error response shape.
- Keep database access behind the repository/service layer.
- Add or update tests for behavior changes.`}
</CodeBlock>

<CodeBlock lang="markdown" kind="file">
{`---
paths:
  - "src/**/*.tsx"
  - "app/**/*.tsx"
  - "components/**/*.tsx"
---

# React / UI Rules

- Prefer small, focused components.
- Keep server/client boundaries explicit.
- Do not introduce a new UI library without approval.
- Add accessible labels for interactive elements.`}
</CodeBlock>

<Section id="skills" num="08" title="skills">

Skill, tekrar kullanılabilir prosedürdür ve slash-command entrypoint gibi çalışabilir. Güncel custom workflow'lar için önerilen ana yer <code>.claude/skills/&lt;name&gt;/SKILL.md</code>'dir. Bu dokümanda skill'leri ana kullanıcı arayüzü gibi ele alıyoruz: <code>/plan</code>, <code>/work</code>, <code>/review</code>.

<Callout kind="info">
  <strong>Discovery/path notu:</strong> Project/personal skill için beklenen yapı <code>.claude/skills/plan/SKILL.md</code> şeklindedir; <code>.claude/skills/plan.md</code> düz dosyası skill olarak yüklenmez. Komut olarak yazdığın ad klasör adından gelir: <code>.claude/skills/plan/SKILL.md</code> → <code>/plan</code>. Frontmatter'daki <code>name</code> alanı slash menüsündeki görüntü/display adını değiştirebilir; çoğu skill konumunda yazdığın komut adını değiştirmez. İstisna: plugin root <code>SKILL.md</code> kullanımı.
